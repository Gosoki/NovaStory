## 1. 三条件交互规格

### C · 一次成型（零回路）

```
写创意（1-2 句，≥8 字）→ [自动] AI 生成完整 3 镜头脚本 → 看稿（只读，同屏回显自己写的创意）→ [提交]
```

不能改、不能反馈。对应现实：一键生成工具。

> 📍 **2026-09-01（§8）：C 的操纵现在包含「事前告知」**。`round.instr_C` 在**写创意之前**就明说
> 「⚠️ 本轮只生成一次，出来以后不能修改也不能重新生成」，提交按钮也从「满意了，提交这一版」
> 改成中性的「提交这一版，进入问卷」（原措辞暗示存在一个可以不满意、可以重来的版本）。
> 同时在只读页回显被试自己写的创意（C 是唯一没有对话历史面板的条件）。
> **这不是纯呈现改动**：这段话就印在被试写意图的那一屏上，而意图文本是全部保真测量的锚
> （`imagine` / `violation` / embedding Δ 都以它为参照），`t_read_intent` 也从这里起算。
> 可能的方向：被试知道只有一发 → 意图写得更长更具体（抬高 C 的保真，压 E−C），
> 或预期更差 → 期望落差压低所有权/满意度（抬高 E−C）。**拉丁方吸收不了这一项**，
> 论文的 C 描述必须写成「一次成型 **且被试事前知情**」。
> ⚠️ 尚未拍板的配套项：目前只有 C 的说明带 ⚠️ 标记，D/E 是平铺直叙 —— 提示强度不等。
> 要不要给 D/E 也加一句同等显著的「本轮可以反复修改」，见 `13 §⑦-C`。

> **设计留档（为什么不强化 C）**：曾讨论把 C 改为「多次生成（重 roll）」或「pick-from-3」以增强与 E 的可比性，**结论：维持一次成型**。理由：
> ① 「多次生成」= 无方向迭代 ≈ 退化版 D；「pick-from-3」= 选择式（生成后识别偏好），与 E（生成前表达意图）是**对立两端**，不会变「可比」，只会成为另一种工作流；
> ② 加第 4 条件破坏平衡设计（被试做 4 轮更长，或改被试间掉功效）；
> ③ C 的价值就是「**零介入地板锚点**」，强化它 = 挪走标尺零点；
> ④ **反直觉坑**：pick-from-3 给一点选择感会**抬高 C 的所有权 → 压缩 E−C 所有权差 → 反伤主出圈点**。
> 「赢 C 太易」的正解不是强化 C，而是**贡献压 E vs D**；选择式（pick-from-N，对应 Midjourney 四宫格 / regenerate）留作 Discussion / future work 的设计空间划界。

### D · 先生成，再修改（常规 ChatGPT 工作流的代理）

```
写创意 → [自动] AI 生成完整脚本
       → 看稿页：脚本本身是【常驻可编辑文本框】+「告诉 AI 怎么改」聊天框常驻
            ├ 直接在稿子上手改（无需保存按钮）
            ├ 给 AI 反馈（可抽象如「更搞笑」，也可具体）→ AI 修订 → 新版本
            └ [满意了，提交这一版]
       循环无上限
```

**页面文案须明示三种玩法**：可以给 AI 抽象方向、可以提具体细改、也可以自己动手改。

### E · 先引导，再生成（本研究提出的工作流）

```
写创意
→ 【第 1 轮引导】AI 一次生成 5-7 问
     固定 3 维：主角欲望·动机 / 关键转折 / 核心画面·构图
   + AI 根据创意补 2-4 个其他维度（tone / ending / sound / detail 等，自由补）
     每问 = 问题 + 一行「为什么问」小字 + 3-4 个选项 + 「✍ 自己写」 + 「🤖 交给 AI 决定」
     逐条展示、可回看上一问、答完一并提交
→ [自动] AI 按创意 + 回答生成完整脚本（**无大纲层**）
→ 看稿页：可编辑文本框常驻 + 「让 AI 继续引导」按钮
     ├ 直接手改
     ├ 继续引导 → AI 读当前稿（含手改）出 1-3 个新问题 → 作答 → AI 修订
     └ [满意了，提交这一版]
   循环无上限
```

E **没有**自由文字反馈通道（那是 D 的机制；想表达具体想法走「自己写」或手改）。

**⛔ 引导 prompt 硬禁令**：AI **不得**就镜头时长 / 秒数如何分配向被试提问（round1 与 followup 两处 prompt 均已三语补齐禁令）。理由：生成 prompt 本就让 AI 自行分配每镜时长，再回头问新手「15 秒怎么切给三镜」是冗余、且新手答不出，只膨胀提问数与前期耗时。

### 全条件通用硬规则

> **任何「提交」或「交给 AI」（修订/引导）动作之前，必须先把用户当前手改后的稿子持久化为最新版本**；AI 的修订永远基于用户最新稿。每一版脚本快照入库并标注作者（`ai` / `user_edit`）。
> 实现位：三按钮的处理函数第一步统一调用「落盘未保存手改」。

### E 允许手改的可行性论证（留档）

- ✅ **假设反而更可检验**：E 与 D 共享「手改 + 提交」，唯一系统性差异 = 事前引导 + AI 通道类型。核心主张「事前引导减少事后修改」**能被直接测量**。E 用户若仍大量手改，假设被证伪——可证伪性是优点。
- ✅ **生态效度高**：不许手改才是反常的；且「E 用户其实不怎么用引导、光手改」这种行为本身就是有价值的发现。
- ⚠️ **代价（已接受）**：D vs E 是**双差异**，不是单变量 → 论文把 D 明确定位成「**常规 ChatGPT 工作流**」的代理，叙事定为「提出的工作流 vs 现状工作流」；因果落在工作流包层（见 [01 §3.3](01_研究定位与主张.md)）。

## 2. 平衡设计：18 种序列（Williams × 题目轮换）

> ⚠️ **这是 2026-07-19 的重大修正，旧文档里的「3×3 拉丁方 / 9 序列 × 4 人」全部作废。**

第 N 个通过筛查的**真实**被试拿 `seq = N % 18`（dev 测试被试不计入；写锁内 `BEGIN IMMEDIATE` 原子分配，并发不撞号）。

- **6 种条件顺序 = C/D/E 全排列（Williams 设计）** × **3 种题目轮换** = **18 系列**
- 每个条件在**每个轮次位置**、与**每个题目**的配对、被**每个条件紧跟**——均恰好配平（实测各 6 次）
- **N = 36 → 每 seq 目标 2 名完成者**

**为什么必须是 Williams**：旧的 3 循环序列（CDE/DEC/ECD）单向转圈，**D 永远紧跟 C、E 永远紧跟 D**，把招牌对比 **E−D 与一阶顺序残留混淆**。Williams 设计使一阶残留配平，E−D 不再与顺序交络。

**停止规则（超招募吸收流失）**：发号按报名数轮转，但**不在「发满 36」就停——招到每个 seq 的完成者（`status='done'`）都达标为止**，流失者占的号靠超招募补齐。研究员后台「各 seq 完成数」块实时看平衡。
→ 因此对外口径写 **N ≥ 36**，不是恰好 36。

代码：`core/state.py:_COND_ORDERS`（6 全排列）× `_TOPIC_ORDERS`；`core/config.py:LATIN_SQUARE_N = 18`；`state` 有断言同步。

## 4. 被试与「零基础新手」的操作化

- **N ≥ 36**（18 系列 × 各 2 名完成者），**日本大学内大学生**（2026-06-26 拍板），**无偿志愿者**（2026-07-02 拍板；伦理材料按无报酬写）。
- 单人一次会话走完，**软目标 10-15 分钟**（上限 ~20 分钟）。
- **不设入口门槛**：任何人都能完成实验（降低招募摩擦、保留演示用途），novice 由背景问卷**测量并记录**。
- **novice 五项操作化（严格 AND）**：① 短视频平台发布作品数 = 0；② 无影视/传媒/设计专业背景；③ 从未写过分镜/脚本；④ 熟练度自评 ≤ 2；⑤ 分镜术语小测 ≤ 1 对。
  代码常量：`analysis/prereg.py: NOVICE_DEF`。
- ✅ **novice 的分析定位（B1 拍板，2026-08-03）**：**招募端不设门槛（随机找人）**；`is_novice` 子集 = **事前确定的主分析人群**；全样本作稳健性分析；明显有创作经验的被试另作 **「経験あり vs なし」对比 / 调节分析**（H8）。
  → 连带：**功效按 novice 子集算**（N 更小），**超招募到子集也达标**为止，不是「全样本 36 就停」。若达标率低于 40%，退路 = 招募端加软门槛 或 冻结时放宽为 4-of-5。

**事前基线协变量**（同意后第一份问卷即测，**前测防污染**）：
① AI 创作经验 `aiexp_idx`（分类，区别于泛用使用频率）② AI 信任倾向 `trust`（7 点）③ 心理所有权倾向 trait `own_trait`（7 点）。
用途：H1-H3 协变量、H7 反向分支异质性、把「天生易有归属感」与「E 提升的状态所有权」分离（H1 混淆控制）。
控制需求（H3 trait）经权衡**未纳入**（状态 agency 已由 soa 每轮测；题量取舍）。
**满意度 / 整体偏好属结果测量，不放事前问卷**（已实装为每轮满意度 + 三轮后 final_survey）。

## 5. 运行流程（与代码对应）

```
打开链接
  → 知情同意页（顶部选语言：日本語/中文/English，默认 ja，仅此一次；之后只有管理员能切）
      （「勿刷新」提示 + 勾选同意 + 开始）
  → 背景问卷（12 项：9 道单选 + 3 项 7 点刻度，约 1-2 分钟；不淘汰任何人，novice 只作记录）
  → 自动分配序列 seq（§2），并把续接 token 写入网址（?t=…）  ← state.enter_intro
  → 说明页「はじめる前に」（views/intro.py）                  ← 2026-09-01 起在问卷之后
      （点「开始」才 state.begin_rounds → 落 round_start，说明页停留不进 t_read_intent）
  → 第 1 轮 → 第 2 轮 → 第 3 轮
  → 总问卷 final_survey（4 题：最喜欢哪轮 / 以后用哪轮 / 总体满意度 7 点 / 自由留言）
  → 完成页（显示 8 位完成码）
```

每一轮的骨架：**读题卡 → 写 1-2 句故事创意（≥8 字）→ 条件流水线（§1）→ 本轮问卷**。
页面顶部有进度条与步骤条（当前步高亮），三条件的步骤条各自如实展示自己的流程。

### 5.1 说明页「はじめる前に」的设计意图（重要，别改坏）

> 📍 **2026-09-01 位置调整**：说明页与背景问卷**对调**，现在夹在「背景问卷 → 第 1 轮」之间。
> 理由：说明页是被试动手前最后读到的东西，排在 12 项问卷之前会被问卷挤出记忆。
> 代价与实现要点：
> - 被试身份与续接 token 在**筛查提交时**就写好（`state.enter_intro`），所以在说明页刷新
>   照样续接，不会插第二行被试、不会再吃一个 seq；
> - `round_start` **不**在这里落，而在说明页的「开始」按钮上（`begin_rounds`），
>   否则整个说明页的停留会被折进第 1 轮的 `t_read_intent`；
> - intake 总时长的口径随之改为 `consent_shown → intro_continue`（`analysis/events.py`）；
> - 未答完第 1 轮的被试续接时**落回说明页**（`state._attempt_resume`），
>   免得在说明页刷新的人从此再也看不到标准化说明；
> - ⚠️ **说明页现在落在「已消耗 seq」的窗口之内**：被试行与 Williams `seq` 在筛查提交时
>   就分配了，在说明页上放弃的人会白吃掉一个 seq 并留下一行 `in_progress`（换序前
>   这种放弃不留任何行）。已知并接受 —— 由既有的**超招募停止规则**（§2）吸收；
>   若日后想省掉，做法是把 seq 分配推迟到第一次 `round_start`；
> - 说明页的「开始」调 `state.start_rounds()`，**不重建** `round_plan`（计划在
>   `enter_intro` 里就装好了）：在这里重读 `topics.json`，只要研究员在被试读说明页的
>   两分钟里动过题库，就会把 RuntimeError 抛在一个已经吃掉 seq 又没有出路的被试脸上。

为什么不是在输入框里塞内容模板：**会污染保真基线**；若加结构化提示 **= 泄漏 E 的操纵**。
所以改为**同意后加一页统一说明**（标准化暴露、条件/内容中立）：

- 流程小图（写想法 → AI 生成 → 改 → 问几个问题）
- **意图自由度文案**：「完整脚本 / 粗略想法 / 只给走向 / 只给基调都行，长短随意」+「零经验、无正解」
- **中立例题（「寝坊した朝」）配 5 档参考输入**（短脚本 / 描写经过 / 只写基调 / 只写人物 / 只写反转，各自独立「答案框」样式）
- **5 档参考输入逐条编号**（例1…例5，编号用强调色，档与档之间留白分隔），两句引导语（「例：お題が…」「そして、AI が…」）用同一种强调色 + 下划线，读起来是同一类句子（2026-09-01）
- **成品分镜样例**：该例题的真 gpt-4o-mini 输出，用与被试同款絵コンテ表渲染（`views/_storyboard.py` 共享组件），**半尺寸**（`render(mini=True)` → `max-width:50%`，窄屏回到 100%；2026-09-01：整版表格会把说明页压垮。⚠️ 不能用 `zoom:.5` —— 它不缩盒子只缩字，会变成「整幅宽的表格 + 6.9px 的日文」）
  > 🐛 **2026-08-05 修复（影响 onboarding 标准化）**：问卷页的「滚动钉住」CSS 此前**无差别作用于所有**絵コンテ表，说明页这张没有配套 JS 去解除它的 `opacity:0`，因此在 **≥ 900 px 宽屏上样例分镜完全不可见**（窄屏才显示）。即此前的试测里，宽屏被试没看到过这一环。现已把钉住行为收进 `pin=True` 开关，说明页走普通流内渲染。**若已有试测数据，其 onboarding 暴露与文档描述不符，需按此重新判读。**
- 例题**刻意用非实验题**、并注明「真题下轮才出」——只教「写多少 / 什么形式」，不锚定真题内容、条件中立不泄漏 E

> ✅ **下限已对齐文案（B6 拍板，2026-08-03）**：`MIN_INTENT_CHARS` **10 → 8**，让「明るい話にしたい」这类只给基调的输入能通过；8 仍非零，保真基线不会失锚。

### 5.2 刷新 / 断网不丢数据（URL token 续接）

续接 token 在网址里，刷新或重连后从 DB 重建身份与序列，跳回第一个没答完问卷的轮次（该轮从头重做，`INSERT OR REPLACE` 防重复行），计时锚点重新落 `round_start`。
被试若丢弃带 token 的网址、从原始邀请链接重进，才会留下一行 `in_progress` 旧记录。
（选 URL token 而非 cookie：cookie 需第三方组件写 + 异步首跑陷阱；单次坐完的实验 URL 已覆盖刷新/断网。）

## 6. 每轮问卷（含分镜表回顾）

问卷**开头**先把终稿渲染成分镜表（No. / 景别·カメラ / 画面 / 情节 / 台词；3 镜连续编号 + 第 4 行留空）供被试对照。解析失败时退回纯文本，不出破表。

> 📐 **分镜文本排版（2026-09-01 起，三语齐）**：编号**独占一行**，其下**分两行**——第一行只有
> 【画面描写】/【画面】/【Visual】，第二行是【时长】X 秒 【拍法】 【台词/音效】，镜与镜之间空一行。
> 动机是 D/E 的可编辑文本框：一坨挤在一行时被试很难定位要改哪一句。
> 字段标记与顺序改动**必须同步** `core/prompts.py`（script + revision，各三语）与
> `core/shots.py`（`_FIELD_RE` / `_VISUAL_START_RE` 兜底切分）——见 §10 硬约束③。

**滚动行为（`views/questionnaire.py` 的观察者 + `_storyboard.render(pin=True)`）**：分镜表先跟随页面正常滚动；滚过约半张后淡着缩到右上角小图（悬停放大回看、移开复原），既随时可查又不占答题视野。窄屏（< 900 px）不启用，回退成普通表格。
> 🐛 **2026-08-05 修复**：占位高度原本只在**会话内首次**进问卷时测一次，于是第 2/3 轮（以及研究员用 devtools 切条件后重进）占位塌陷为 0，题目上移到 `position:fixed` 的分镜表底下——**前 9 道题被整张挡住**，且页面变短导致小图收不起来。同时修掉「钉向右上角的动画会把整张纸从题目上方拉过去」。已用无头浏览器逐帧回归（换轮 / fragment 重绘 / 频繁滚动 / 跳跃滚动）。

**「画面」列配图（仅当正式模型 = OpenAI 时开启，`core/imagegen.py`）**：
提交这一版后进入问卷 → 页面立刻显示、画面列先显示「生成中…」→ 后台守护线程用 **gpt-image-1-mini** 并行生成 3 张手绘风插图（锁定简笔风格）、逐张原子写盘 → 问卷里的分镜表用 `st.fragment(run_every=2)` 轮询磁盘、好一张显示一张、全好后停轮询。
**全程非阻塞、失败即静默降回占位，绝不打断实验**；生图在**提交之后**发生，**不进创作净时长**（t_pregen/t_postgen）。图落 `data/storyboard_images/{被试}_{轮次}/`（留档，已 gitignore）。非 OpenAI（开发期 edgefn）时保持空占位「今後実装予定」。

> ⚠️ **效度注记（必须写进论文）**：配图在**问卷阶段可见**，被试是「看着插图」回答所有权 / imagine_match / violation → **保真/所有权 DV 现在含视觉成分**。被试内设计使其在 C/D/E 间均等（**不偏 E−D 主对比**），但改变了 DV 的构念解释；这是研究者知情决定。
> 另注：说明页样例的插图很漂亮，正式轮画面列在**非 OpenAI 时**仍是空框 → 期待落差；开 OpenAI 即消解。

**题目**：所有权 3 题 + 主导感 2 题 + 负荷 1 题 + 意图违背 1 题 + 想象匹配 1 题 + **本轮满意度 1 题** （以上均为 1-7 分段按钮、强制作答）+ 逐镜头标注 3 题（**每镜三选一**：`mine / ai_ok / ai_against`，强制作答；终稿解析失败时降级为整稿 1 题）；**第 2 轮**含注意力检查（「请选 2」）。
**E 轮额外 3 题（C/D 不显示、存 NULL）**：`ai_q_quality`（引导问题质量 1-7）、`ai_q_amount`（问得多还是少 1-7：1=太少·4=刚好·7=太多）、`ai_q_best`（选填多选，从本轮 AI 问过的问题里勾出有帮助的若干道，每道附被试当时的回答便于辨认）。→ 探索性，收数后讨论。

## 7. 分支与特殊情况

| 情况 | 行为 |
|---|---|
| 引导问题 JSON 解析失败（重试 2 次后） | 该轮退化为 1 个开放问题（「用几句话补充你想要的方向」），记 `fallback=true`，流程不断；fallback 开放题**不可空提交** |
| E 追问引导生成失败 | 报错 + 重试按钮 + **「返回草稿」出口**（不会锁死在引导页） |
| 终稿没按编号模板 | 解析器改用「每镜的首字段」兜底切分（**新排版 = 画面/画面描写/Visual**，旧排版 = 时长/秒数，两种都试、取切得更多的那种）；兜底判定不可靠时**诚实失败**：逐镜头标注降级为整体 1 题、`parse_ok=0` |
| LLM 调用失败 | 报错 + 重试按钮；events 记 `llm_error`；**失败等待计入 `t_llm_wait`，不污染创作净时长** |
| LLM 返回空 choices / None content | 判空当解析失败 → 重试 → `LLMJsonError` → 降级 fallback 开放题（不再崩溃） |
| 创意 < 8 字 / 引导某问没作答 / 修改要求为空 / 问卷漏答 | 拦截提示 |
| D/E 用户全程不用 AI 通道、只手改或直接提交 | 允许，本身就是行为数据 |
| E 用户全部「交给 AI 决定」 | 允许，引导剂量趋零，记录在案 |
| 刷新 / 断网重连 | URL token 续接（§5.2） |
| 中途彻底流失（丢弃网址） | participants 留 `in_progress`，**不进主分析**（2026-07-02 拍板①） |

## 8. 模型配置

- 开发期 = secrets 第 1 个配置（edgefn 免费网关，当前 KAT-Coder）
- **正式实验全程 OpenAI**（B9 拍板 2026-06-26）——把 secrets 首个配置换成 OpenAI 即可；引导步同主模型（`GUIDANCE_API_INDEX=None` 跟随主配置）

### 8.1 选型（2026-08-03 实测）

| 阶段 | 模型 | 说明 |
|---|---|---|
| **开发 / 试测（现在）** | `gpt-4o-mini-2024-07-18` | 便宜、够快，机械规格全过。**现用中** |
| **正式采数（换过去）** | **`gpt-5.4-mini-2026-03-17`** | 引导问题质量明显更好，规格违反 0/20 |

**选型方法**：拿本项目真实 prompt（`build_system_script` / `build_system_guidance_round1` 等，日语，真三题）跑 9 个候选，不查参数表。

**延迟（3 次中位数）**——不是区分点，全在 8s 内，引导步进度条封顶 60s：

| 模型 | 脚本 TTFT | 脚本总 | 引导总 |
|---|---|---|---|
| gpt-4o-mini-2024-07-18 | 0.9s | 3.1s | 4.7s |
| gpt-5.4-mini-2026-03-17 | 0.5s | 2.9s | 5.5s |

**成本（实测 token × 官方价，N=45、含 2.5× 修订/追问/重试系数）**——也不是区分点：
gpt-4o-mini **$0.11** / gpt-4.1-mini $0.33 / gpt-5.4-nano $0.31 / **gpt-5.4-mini $1.14** / gpt-5.1 $3.39。
实测 `reasoning_tokens = 0`，gpt-5.4 系无隐藏推理开销。

**真正的区分点 = E 引导问题的具体性**。E 的问题**本身就是干预**，问题空泛 = 操纵变弱，这是处理效度问题而非外观问题。同一创意、同一 seed：

> **gpt-4o-mini**：「拾った切符を見た主人公が一番手に入れたいものは何ですか？」→ 他人の感謝 / 良心の安らぎ / 冒険の興奮
> **gpt-5.4-mini**：「切符を拾った主人公が、いま一番手放したくないのは『自分でその切符を使ってしまう得』と『落とし主を困らせたくない気持ち』のどちらですか？」→ 自分で使って得をしたい / 落とし主を困らせたくない / 面倒ごとを避けて早く済ませたい / 誰かに見られて後ろめたい思いをしたくない

前者是抽象名词三选一（新手答不出所以然），后者把创意里的**具体两难**摆出来、选项互斥且落在情节上——正是 B4 prompt-review 要求的「点到具体情节，别套模板」。

### 8.2 稳定性实测（各 20 次，10 种真实新手风格创意 × 3 题）

> 关心的是被试真会撞上的坏路径，不是平均质量。

| 指标 | gpt-4o-mini | gpt-5.4-mini |
|---|---|---|
| 引导 JSON 首次解析成功 | 100% | 100% |
| 问数在 5-7 | **95%** | **100%** |
| 三固定维齐全 | 100% | 100% |
| 选项数在 3-4 | **95%**（出现过 **2 选项**）| **100%**（最少 3） |
| 问秒数分配（违规） | 0% | 0% |
| 脚本解析成 3 镜 | 100% | 100% |
| 时长合计 = 15 秒 | 100% | 100% |
| 引导延迟 中位 / p95 | 5.5s / 8.3s | 6.6s / 10.5s |
| 脚本延迟 中位 / p95 | 2.6s / 3.5s | 3.3s / 5.4s |
| API 例外 | 0/20 | 0/20 |

**读法**：① **引导降级（fallback）实际上不会发生**——JSON 首次解析 40/40 全过；代码还有 2 次重试，`p³` 后概率可忽略。这条正式回答了 [06 ⑩](06_待拍板事项.md) 挂着的「引导数量约束只靠 prompt，待试测实测」。
② `parse_ok=0`（丢逐镜头保真那条腿）在两个模型上都**没出现过**。
③ **唯一的真实差距**：gpt-4o-mini 有 ~5% 概率产出**违反「必 3-4 选项」硬底的 2 选项题**或问数越界，且**代码不做实时校验**（会原样呈现给被试）；gpt-5.4-mini 20/20 零违规。N=45 下 ~5% ≈ 2 名被试会撞上。

### 8.3 B4 提示词校验（两个模型都过）

全路径 × 真三题 × ja：脚本 3 镜/15 秒 ✓、引导 r1 5-7 问·三固定维全·选项 3-4 ✓、追问 1-3 问 ✓、D 修订仍合规 ✓、**秒数分配提问 0 次** ✓。
> ⚠️ 之前一版实测把 GPT-5 系标成「秒漏」是**误报**——正则匹配到了把「15秒」当背景的说法（「15秒の中で…転換はどこ？」），不是被禁止的「每镜各分几秒」。用只抓时长分配问句的正则复测后 **0 违规**。

### 8.4 其他两个模型槽

#### 配图模型 —— ✅ 已换成 `gpt-image-1-mini`（2026-08-03 实测）

> **既定事项（2026-08-03）**：配图模型锁定 `gpt-image-1-mini`（`core/imagegen.py:_IMG_MODEL`）。

**全 6 个图像模型实测**（3 张并行 × 2 轮，同一套 `_STYLE` 风格锁，压到与线上一致的 512×512 JPEG = 被试实际看到的东西）：

| 模型 | 3张并行 | 出力tok | $/张 | 全研究(405张) | 彩度 | 连通成分 | 微小碎片 |
|---|---|---|---|---|---|---|---|
| gpt-image-1（原用） | 17.9s | 272 | $0.0109 | $4.4 | 1.1 | 10 | 4 |
| **gpt-image-1-mini ← 采用** | **13.7s** | 272 | **$0.0022** | **$0.9** | **0.0** | **5** | **0** |
| gpt-image-1.5 | 9.9s | 410 | $0.0131 | $5.3 | 0.0 | 86 | 80 |
| gpt-image-2 | 22.8s | 196 | $0.0059 | $2.4 | 0.0 | 264 | 238 |
| gpt-image-2-2026-04-21 | 25.8s | 196 | $0.0059 | $2.4 | 0.0 | 264 | 238 |
| chatgpt-image-latest | 13.3s | 555 | 价格未公布 | — | — | — | — |

**决策依据（按权重）**：
1. **最便宜且差距决定性** —— $0.0022/张，比第二便宜的 gpt-image-2 还便宜 **2.7 倍**、比 gpt-image-1.5 便宜 **6 倍**。（gpt-image-2 出力 token 更少 196 vs 272，但单价 $30/1M vs $8/1M，算下来仍贵 2.7 倍。）
2. **零安全拒绝**（见下）。
3. **线条最干净** —— 彩度 **0.0**（原 gpt-image-1 有 1.1 轻微串色，而风格锁明写 "No color"）、连通成分 5 / 微小碎片 0。`gpt-image-1.5` 与 `gpt-image-2` 笔画**严重碎裂**并出现阴影块，违反 `_STYLE` 的 "clean thin uniform black outlines / NO shading"。
4. **速度不是区分点** —— 最快的 gpt-image-1.5（9.9s）只比 mini（13.7s）快 3.8 秒，却贵 6 倍。配图在**问卷阶段后台生成**，问卷本身 60-90 秒，这点差别被试**完全感知不到**。

**参数已在最省档，不要再「优化」**（已钉成 `core/imagegen.py` 调用点的注释）：`256x256`/`512x512` → **400 Invalid size（不支持）**，1024×1024 是最小可选；`size="auto"` 会选 1536×1024 **贵 47%**，必须写死；`quality` low=272 tok，medium/high·auto 分别贵 **3.9× / 15×**。
→ 「生成 1024 再缩到 512 存盘」**不是浪费**，1024 就是生成下限。

对照图与完整指标 → `samples/imggen/README.md` + `model_bench_2026-08-03.jpg`。

**追测：安全系统拒绝率（各 42 次）** —— 选型时漏掉的一项。OpenAI 图像安全系统会**偶发拒绝**（400 "rejected by the safety system"），即便提示词是完全无害的分镜描述：

| 模型 | 42 次成功 | 安全拒绝 |
|---|---|---|
| **gpt-image-1-mini（现用）** | **42/42（100%）** | **0**（全部 60+ 次尝试中一次都没有） |
| gpt-image-2-2026-04-21 | 39/42（93%） | **3（每一批都出现）** |

被拒 → 写 `.done` → 回退空占位，**不打断实验**，但那一格没有插图。按 405 张算，7% ≈ **28 格缺图**且分布不均。

> ⚠️ **图像模型没有带日期快照可钉** —— 账号里唯一带日期的是 `gpt-image-2-2026-04-21`。**没有选它**，因为钉快照的意义是「别让 DV 里的视觉成分中途变化」，而它 **7% 的拒绝率会当场制造 ~28 格缺图**——用一个**确定的、现在就发生的**不一致，换一个**假设的、将来才可能发生的**漂移，不划算；何况它还慢 78%、贵 2.7 倍。
> 这是 **B7「钉日期快照」规则的已知例外**。缓解：① 配图不是 DV；② 被试内在 C/D/E 均等，漂移**不偏 E−D 主对比**；③ 每张图归档在 `data/storyboard_images/`，事后可复算风格指标检测漂移。Limitations 写明。

#### Embedding —— ⚠️ 真缺口，见 [03 §4.1](03_测量与数据字典.md)

OpenAI 只有 `text-embedding-3-small/large` + ada（同家族），凑不出保真 Δ 方案要求的「≥3 个异构日语模型」。**必须补非 OpenAI 的模型**，否则 embedding 那条腿只是「同一家的两个尺寸」。
- 所有调用的 model / temperature / base_url **逐 trial 入库**；每次 LLM 调用的 token 用量记入 `events.llm_done.payload.usage`
- ✅ **模型已钉死日期快照（B7，2026-08-03）**：`gpt-4o-mini-2024-07-18`（不用浮动别名 `gpt-4o-mini`——别名会在采数中途被重新指向新模型）。
- ✅ **每次调用发送 per-trial 派生 seed** `(participant_id×100 + round_idx)`，并把 seed + `system_fingerprint` 记进 `llm_done` 事件的 `payload.repro`。
- ⚠️ **输出不是逐字可复现的**——实测 gpt-4o-mini 在 temperature=0 + 固定 seed 下 5/5 次输出仍不同（`system_fingerprint` 相同）。目标因此定为**配置可复现 + 漂移可检测**，不是 bitwise 复现。temperature 维持 **0.8**（创作任务需要；确定性既然拿不到，调 0 只改变产物性质而无收益）。详见 [06 ⑦](06_待拍板事项.md)。
