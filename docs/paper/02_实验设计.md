## 1. 三条件交互规格

### C · 一次成型（零回路）

```
写创意（1-2 句，≥8 字）→ [自动] AI 生成完整 3 镜头脚本 → 看稿（只读）→ [提交]
```

不能改、不能反馈。对应现实：一键生成工具。

> **设计留档（为什么不强化 C）**：曾讨论把 C 改为「多次生成（重 roll）」或「pick-from-3」以增强与 E 的可比性，**结论：维持一次成型**。理由：
> ① 「多次生成」= 无方向迭代 ≈ 退化版 D；「pick-from-3」= 选择式（生成后识别偏好），与 E（生成前表达意图）是**对立两端**，不会变「可比」，只会成为另一种工作流；
> ② 加第 4 条件破坏平衡设计（被试做 4 轮更长，或改被试间掉功效）；
> ③ C 的价值就是「**零介入地板锚点**」，强化它 = 挪走标尺零点；
> ④ **反直觉坑**：pick-from-3 给一点选择感会**抬高 C 的所有权 → 压缩 E−C 所有权差 → 反伤主出圈点**。
> 「赢 C 太易」的正解不是强化 C，而是**贡献压 E vs D**；选择式（pick-from-N，对应 Midjourney 四宫格 / regenerate）留作 Discussion / future work 的设计空间划界。

### D · 先生成，再修改（常规 ChatGPT 工作流的代理）

```
写创意 → [自动] AI 生成完整脚本
       → 看稿页：脚本本身是【常驻可编辑文本框】+「告诉 AI 怎么改」聊天框常驻
            ├ 直接在稿子上手改（无需保存按钮）
            ├ 给 AI 反馈（可抽象如「更搞笑」，也可具体）→ AI 修订 → 新版本
            └ [满意了，提交这一版]
       循环无上限
```

**页面文案须明示三种玩法**：可以给 AI 抽象方向、可以提具体细改、也可以自己动手改。

### E · 先引导，再生成（本研究提出的工作流）

```
写创意
→ 【第 1 轮引导】AI 一次生成 5-7 问
     固定 3 维：主角欲望·动机 / 关键转折 / 核心画面·构图
   + AI 根据创意补 2-4 个其他维度（tone / ending / sound / detail 等，自由补）
     每问 = 问题 + 一行「为什么问」小字 + 3-4 个选项 + 「✍ 自己写」 + 「🤖 交给 AI 决定」
     逐条展示、可回看上一问、答完一并提交
→ [自动] AI 按创意 + 回答生成完整脚本（**无大纲层**）
→ 看稿页：可编辑文本框常驻 + 「让 AI 继续引导」按钮
     ├ 直接手改
     ├ 继续引导 → AI 读当前稿（含手改）出 1-3 个新问题 → 作答 → AI 修订
     └ [满意了，提交这一版]
   循环无上限
```

E **没有**自由文字反馈通道（那是 D 的机制；想表达具体想法走「自己写」或手改）。

**⛔ 引导 prompt 硬禁令**：AI **不得**就镜头时长 / 秒数如何分配向被试提问（round1 与 followup 两处 prompt 均已三语补齐禁令）。理由：生成 prompt 本就让 AI 自行分配每镜时长，再回头问新手「15 秒怎么切给三镜」是冗余、且新手答不出，只膨胀提问数与前期耗时。

### 全条件通用硬规则

> **任何「提交」或「交给 AI」（修订/引导）动作之前，必须先把用户当前手改后的稿子持久化为最新版本**；AI 的修订永远基于用户最新稿。每一版脚本快照入库并标注作者（`ai` / `user_edit`）。
> 实现位：三按钮的处理函数第一步统一调用「落盘未保存手改」。

### E 允许手改的可行性论证（留档）

- ✅ **假设反而更可检验**：E 与 D 共享「手改 + 提交」，唯一系统性差异 = 事前引导 + AI 通道类型。核心主张「事前引导减少事后修改」**能被直接测量**。E 用户若仍大量手改，假设被证伪——可证伪性是优点。
- ✅ **生态效度高**：不许手改才是反常的；且「E 用户其实不怎么用引导、光手改」这种行为本身就是有价值的发现。
- ⚠️ **代价（已接受）**：D vs E 是**双差异**，不是单变量 → 论文把 D 明确定位成「**常规 ChatGPT 工作流**」的代理，叙事定为「提出的工作流 vs 现状工作流」；因果落在工作流包层（见 [01 §3.3](01_研究定位与主张.md)）。

## 2. 平衡设计：18 种序列（Williams × 题目轮换）

> ⚠️ **这是 2026-07-19 的重大修正，旧文档里的「3×3 拉丁方 / 9 序列 × 4 人」全部作废。**

第 N 个通过筛查的**真实**被试拿 `seq = N % 18`（dev 测试被试不计入；写锁内 `BEGIN IMMEDIATE` 原子分配，并发不撞号）。

- **6 种条件顺序 = C/D/E 全排列（Williams 设计）** × **3 种题目轮换** = **18 系列**
- 每个条件在**每个轮次位置**、与**每个题目**的配对、被**每个条件紧跟**——均恰好配平（实测各 6 次）
- **N = 36 → 每 seq 目标 2 名完成者**

**为什么必须是 Williams**：旧的 3 循环序列（CDE/DEC/ECD）单向转圈，**D 永远紧跟 C、E 永远紧跟 D**，把招牌对比 **E−D 与一阶顺序残留混淆**。Williams 设计使一阶残留配平，E−D 不再与顺序交络。

**停止规则（超招募吸收流失）**：发号按报名数轮转，但**不在「发满 36」就停——招到每个 seq 的完成者（`status='done'`）都达标为止**，流失者占的号靠超招募补齐。研究员后台「各 seq 完成数」块实时看平衡。
→ 因此对外口径写 **N ≥ 36**，不是恰好 36。

代码：`core/state.py:_COND_ORDERS`（6 全排列）× `_TOPIC_ORDERS`；`core/config.py:LATIN_SQUARE_N = 18`；`state` 有断言同步。

## 3. 题目（3 个日本日常微情境，已冻结）

`data/topics.json`，字段 `{ja, zh, en}` 三语字典 + `shot_count`(3) + `total_seconds`(15)。

| # | ja | 基调 | 三维抓手 |
|---|---|---|---|
| 1 | 拾った切符（誰かの落とし物） | 意思决定 / 好奇 | 转折强（看/不看·还/留是天然翻转） |
| 2 | 最後のひと口（分け合う / 独り占め） | 关系博弈（可喜剧可温情） | 伸手—收回—让出的清晰转折 |
| 3 | はじめての街の、最初の一歩 | 探索 / 希望 | 开放度上端锚点，方向自由 |

**设计依据（均已联网核实 [A]）**：适度约束促创意（Haught-Tromp《Green Eggs and Ham》2016）、歧义投射诱发多样解读（TAT）、叙事框架多样性（ReelFramer CHI 2024）、每题 = 一条 log line（Dramatron CHI 2023）、低门槛可完成（CineVision UIST 2025）、拉丁方需先 norming（Lewis 1989）。

**⚠️ 为什么换掉旧三题**（満員電車 / バイト最終日 / 合格発表）：① 情绪基调高度同质（全是「受阻·无力·克制」）→ 压低多样性；② 开放度未校准且偏低 → 削弱保真区分度与所有权操纵空间；③ 转折维贫瘠（多为静态受阻）→ E 的 turning_point 提问空转。三者系统性压低三个核心因变量的可测方差。

**机器基线 norming（已跑，2026-07-18，`analysis/norming.py`，OpenAI gpt-4o-mini ×12/题）**：
三题**规格 100% 合规**（均 3 镜 / 15 秒 / 字段齐全）；开放度代理 **gzip_cr = 3.222 / 3.202 / 3.190（极差 ~1%）**、distinct-2 = 0.373 / 0.376 / 0.394、self-rep = 0.21 → **开放度高度可比 ✓，题面已冻结**。（embedding 发散度 / 结局枚举 / 三维覆盖为可选增强 norming，后补即可。）这是拉丁方分离题目主效应的前提。

> **⚠️ 冻结后若改 `topics.json`**：`_attempt_resume` 会从 topics.json 实时重建 round_plan，中途改题会静默重配已在进行的被试。采数期间**禁止改题**；结构性修法见 [06 §待判断](06_待拍板事项.md) #22。

## 4. 被试与「零基础新手」的操作化

- **N ≥ 36**（18 系列 × 各 2 名完成者），**日本大学内大学生**（2026-06-26 拍板），**无偿志愿者**（2026-07-02 拍板；伦理材料按无报酬写）。
- 单人一次会话走完，**软目标 10-15 分钟**（上限 ~20 分钟）。
- **不设入口门槛**：任何人都能完成实验（降低招募摩擦、保留演示用途），novice 由背景问卷**测量并记录**。
- **novice 五项操作化（严格 AND）**：① 短视频平台发布作品数 = 0；② 无影视/传媒/设计专业背景；③ 从未写过分镜/脚本；④ 熟练度自评 ≤ 2；⑤ 分镜术语小测 ≤ 1 对。
  代码常量：`analysis/prereg.py: NOVICE_DEF`。
- ✅ **novice 的分析定位（B1 拍板，2026-08-03）**：**招募端不设门槛（随机找人）**；`is_novice` 子集 = **事前确定的主分析人群**；全样本作稳健性分析；明显有创作经验的被试另作 **「経験あり vs なし」对比 / 调节分析**（H8）。
  → 连带：**功效按 novice 子集算**（N 更小），**超招募到子集也达标**为止，不是「全样本 36 就停」。若达标率低于 40%，退路 = 招募端加软门槛 或 冻结时放宽为 4-of-5。

**事前基线协变量**（同意后第一份问卷即测，**前测防污染**）：
① AI 创作经验 `aiexp_idx`（分类，区别于泛用使用频率）② AI 信任倾向 `trust`（7 点）③ 心理所有权倾向 trait `own_trait`（7 点）。
用途：H1-H3 协变量、H7 反向分支异质性、把「天生易有归属感」与「E 提升的状态所有权」分离（H1 混淆控制）。
控制需求（H3 trait）经权衡**未纳入**（状态 agency 已由 soa 每轮测；题量取舍）。
**满意度 / 整体偏好属结果测量，不放事前问卷**（已实装为每轮满意度 + 三轮后 final_survey）。

## 5. 运行流程（与代码对应）

```
打开链接
  → 知情同意页（顶部选语言：日本語/中文/English，默认 ja，仅此一次；之后只有管理员能切）
      （「勿刷新」提示 + 勾选同意 + 开始）
  → 说明页「はじめる前に」（views/intro.py）
  → 背景问卷（12 项：9 道单选 + 3 项 7 点刻度，约 1-2 分钟；不淘汰任何人，novice 只作记录）
  → 自动分配序列 seq（§2），并把续接 token 写入网址（?t=…）
  → 第 1 轮 → 第 2 轮 → 第 3 轮
  → 总问卷 final_survey（4 题：最喜欢哪轮 / 以后用哪轮 / 总体满意度 7 点 / 自由留言）
  → 完成页（显示 8 位完成码）
```

每一轮的骨架：**读题卡 → 写 1-2 句故事创意（≥8 字）→ 条件流水线（§1）→ 本轮问卷**。
页面顶部有进度条与步骤条（当前步高亮），三条件的步骤条各自如实展示自己的流程。

### 5.1 说明页「はじめる前に」的设计意图（重要，别改坏）

为什么不是在输入框里塞内容模板：**会污染保真基线**；若加结构化提示 **= 泄漏 E 的操纵**。
所以改为**同意后加一页统一说明**（标准化暴露、条件/内容中立）：

- 流程小图（写想法 → AI 生成 → 改 → 问几个问题）
- **意图自由度文案**：「完整脚本 / 粗略想法 / 只给走向 / 只给基调都行，长短随意」+「零经验、无正解」
- **中立例题（「寝坊した朝」）配 5 档参考输入**（短脚本 / 描写经过 / 只写基调 / 只写人物 / 只写反转，各自独立「答案框」样式）
- **成品分镜样例**：该例题的真 gpt-4o-mini 输出，用与被试同款絵コンテ表渲染（`views/_storyboard.py` 共享组件）
- 例题**刻意用非实验题**、并注明「真题下轮才出」——只教「写多少 / 什么形式」，不锚定真题内容、条件中立不泄漏 E

> ✅ **下限已对齐文案（B6 拍板，2026-08-03）**：`MIN_INTENT_CHARS` **10 → 8**，让「明るい話にしたい」这类只给基调的输入能通过；8 仍非零，保真基线不会失锚。

### 5.2 刷新 / 断网不丢数据（URL token 续接）

续接 token 在网址里，刷新或重连后从 DB 重建身份与序列，跳回第一个没答完问卷的轮次（该轮从头重做，`INSERT OR REPLACE` 防重复行），计时锚点重新落 `round_start`。
被试若丢弃带 token 的网址、从原始邀请链接重进，才会留下一行 `in_progress` 旧记录。
（选 URL token 而非 cookie：cookie 需第三方组件写 + 异步首跑陷阱；单次坐完的实验 URL 已覆盖刷新/断网。）

## 6. 每轮问卷（含分镜表回顾）

问卷**开头**先把终稿渲染成分镜表（No. / 景别·カメラ / 画面 / 情节 / 台词；3 镜连续编号 + 第 4 行留空）供被试对照。解析失败时退回纯文本，不出破表。

**「画面」列配图（仅当正式模型 = OpenAI 时开启，`core/imagegen.py`）**：
提交这一版后进入问卷 → 页面立刻显示、画面列先显示「生成中…」→ 后台守护线程用 **gpt-image-1** 并行生成 3 张手绘风插图（锁定简笔风格）、逐张原子写盘 → 问卷里的分镜表用 `st.fragment(run_every=2)` 轮询磁盘、好一张显示一张、全好后停轮询。
**全程非阻塞、失败即静默降回占位，绝不打断实验**；生图在**提交之后**发生，**不进创作净时长**（t_pregen/t_postgen）。图落 `data/storyboard_images/{被试}_{轮次}/`（留档，已 gitignore）。非 OpenAI（开发期 edgefn）时保持空占位「今後実装予定」。

> ⚠️ **效度注记（必须写进论文）**：配图在**问卷阶段可见**，被试是「看着插图」回答所有权 / imagine_match / violation → **保真/所有权 DV 现在含视觉成分**。被试内设计使其在 C/D/E 间均等（**不偏 E−D 主对比**），但改变了 DV 的构念解释；这是研究者知情决定。
> 另注：说明页样例的插图很漂亮，正式轮画面列在**非 OpenAI 时**仍是空框 → 期待落差；开 OpenAI 即消解。

**题目**：所有权 3 题 + 主导感 2 题 + 负荷 1 题 + 意图违背 1 题 + 想象匹配 1 题 + **本轮满意度 1 题** + 逐镜头标注 3 题（1-7 分段按钮，强制作答）；**第 2 轮**含注意力检查（「请选 2」）。
**E 轮额外 3 题（C/D 不显示、存 NULL）**：`ai_q_quality`（引导问题质量 1-7）、`ai_q_amount`（问得多还是少 1-7：1=太少·4=刚好·7=太多）、`ai_q_best`（选填多选，从本轮 AI 问过的问题里勾出有帮助的若干道，每道附被试当时的回答便于辨认）。→ 探索性，收数后讨论。

## 7. 分支与特殊情况

| 情况 | 行为 |
|---|---|
| 引导问题 JSON 解析失败（重试 2 次后） | 该轮退化为 1 个开放问题（「用几句话补充你想要的方向」），记 `fallback=true`，流程不断；fallback 开放题**不可空提交** |
| E 追问引导生成失败 | 报错 + 重试按钮 + **「返回草稿」出口**（不会锁死在引导页） |
| 终稿没按编号模板 | 解析器改用「时长/秒数字段」兜底切分；兜底判定不可靠时**诚实失败**：逐镜头标注降级为整体 1 题、`parse_ok=0` |
| LLM 调用失败 | 报错 + 重试按钮；events 记 `llm_error`；**失败等待计入 `t_llm_wait`，不污染创作净时长** |
| LLM 返回空 choices / None content | 判空当解析失败 → 重试 → `LLMJsonError` → 降级 fallback 开放题（不再崩溃） |
| 创意 < 8 字 / 引导某问没作答 / 修改要求为空 / 问卷漏答 | 拦截提示 |
| D/E 用户全程不用 AI 通道、只手改或直接提交 | 允许，本身就是行为数据 |
| E 用户全部「交给 AI 决定」 | 允许，引导剂量趋零，记录在案 |
| 刷新 / 断网重连 | URL token 续接（§5.2） |
| 中途彻底流失（丢弃网址） | participants 留 `in_progress`，**不进主分析**（2026-07-02 拍板①） |

## 8. 模型配置

- 开发期 = secrets 第 1 个配置（edgefn 免费网关，当前 KAT-Coder）
- **正式实验全程 OpenAI**（B9 拍板 2026-06-26；质量稳 / 延迟低 / 30 人 < $5）——把 secrets 首个配置换成 OpenAI 即可；引导步同主模型（`GUIDANCE_API_INDEX=None` 跟随主配置）
- 所有调用的 model / temperature / base_url **逐 trial 入库**；每次 LLM 调用的 token 用量记入 `events.llm_done.payload.usage`
- ✅ **模型已钉死日期快照（B7，2026-08-03）**：`gpt-4o-mini-2024-07-18`（不用浮动别名 `gpt-4o-mini`——别名会在采数中途被重新指向新模型）。
- ✅ **每次调用发送 per-trial 派生 seed** `(participant_id×100 + round_idx)`，并把 seed + `system_fingerprint` 记进 `llm_done` 事件的 `payload.repro`。
- ⚠️ **输出不是逐字可复现的**——实测 gpt-4o-mini 在 temperature=0 + 固定 seed 下 5/5 次输出仍不同（`system_fingerprint` 相同）。目标因此定为**配置可复现 + 漂移可检测**，不是 bitwise 复现。temperature 维持 **0.8**（创作任务需要；确定性既然拿不到，调 0 只改变产物性质而无收益）。详见 [06 ⑦](06_待拍板事项.md)。

## 9. 研究员 / 测试路径

侧边栏「实验员工具」（密码，默认 `nova` ⚠️ 部署必改）：模型连通性测试；数据后台四表浏览/导出；语言切换（含 en，仅管理员）；**跳过同意+筛查**（dev 标记，**不占用真实被试的拉丁方计数**）；**一键填充当前页输入**；**切到 C/D/E**（就地换当前轮条件并重开本轮，计时锚点自动重记）；为下一位被试重置（清续接 token）。

**研究员后台（开研究员模式即见）= 监控 + 分析，全程点鼠标、不用命令行：**
- **🗂 数据管理·监控**（`views/monitor_panel.py`）：概览卡片（完成/进行中/筛除/novice 占比 + 进度条）+ 统计图（条件×题目计数平衡热力表、**各 seq 完成数**、每日完成数、各条件主观均值）+ **数据健康块**（解析失败率 / LLM 报错率 / 引导降级率 / 生成延迟中位·95%）
- **📊 数据分析**（`views/analysis_panel.py`）：① 试测体检（4 生死问题 🟢🟡🔴）② 出分析结果 ③ 出图 ④ 功效分析

手动输入清单：`samples/test_inputs.md`；全自动回归：`.venv/bin/python scripts/dev_smoke_e2e.py`（LLM 打桩，不耗 API，含续接回归）。

## 10. 语言

- 被试默认日语（`ja`）；**ja / zh / en 三语全链路可用**（UI + `prompts.build_*` 输出 + `topics.json` 的 `{ja,zh,en}` 情境 + `core/shots.py` 分镜解析），被试同意页三语可选（默认 ja）；研究员测试用 zh。
- **硬约束**：① `i18n/locales/{ja,zh,en}.json` 三语键树必须一致（占位符也要对齐）；② LLM 输出语言由 `prompts.build_*` 的 `lang` 参数控制（调用点传 `i18n.get_lang()`），每个 `build_*` 都有 zh/en/ja 三分支；③ **改分镜字段标记（【时长】/【Duration】…）时，`prompts.py` 与 `core/shots.py` 解析器必须同步**。
- 分析脚本 `analysis/*.py` 的计算输出仍是中文（纯研究员算力输出，不译）。
