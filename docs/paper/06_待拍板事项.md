## 🟠 ⑫ 被试没有「我要退出」的按钮 —— 要不要加？

同意书写「你可以随时关闭页面退出」。**实现上确实如此**（关页面即止），但：
- 没有主动退出入口 → 想退出的人可能反而**乱答完**（比中途退出更毁数据）
- 数据上分不清「主动退出」和「掉线/网络断」——两者都停在 `in_progress`

**选项**：
- **(a)** 不加（现状）。理由：关页面已够，加按钮反而提示「可以退出」，抬高流失率。
- **(b)** 加一个不显眼的「中断实验」链接 → 写 `status='withdrawn'` + 一句「已记录，感谢」。数据上能把主动退出和掉线分开。
- **(c)** 只在**问卷页脚**加一行小字「不想继续可以直接关闭页面，已完成的部分仍会保留」。零按钮，纯告知。

> 我的建议：**(c)**。拿到「主动退出可辨识」以外的全部好处，且不给犹豫的人一个显眼的出口。

## ✅ ⑲ 关掉标签页重开 = 新被试，会吃掉拉丁方序号 —— **已修（2026-09-06）**

`views/screening.py` 无条件调 `db.insert_participant`，`state._attempt_resume` 只认 URL 里的 `?t=`。Playwright 实测：12 段会话 → 临时库 12 行被试、12 个不同 seq（0..11），**每段都吃掉一个拉丁方 seq**。

**教室场景下这几乎必然发生**（几十台手机，有人手滑关掉再扫一次码），结果是多出走不完的孤儿被试行，**并把后面所有人的条件轮转挪位**。

**已实施 (a)**：带 token 的 URL 存进浏览器 localStorage（`core/state.remember_resume_url`，app.py 每次渲染有 participant 时调用）；同意页检测到存档且 URL 无 token 时，在页面底部给出「继续上次未完成的作答」（`state.offer_resume`）；研究员「重置下一位」会清掉存档（`reset_for_next` → `forget_resume_url`）。三语文案 `consent.resume_hint` / `consent.resume_link`。

实现上有两个绕不开的约束，写在 `offer_resume` 的 docstring 里，**别改回自动跳转**：
- components/`st.iframe` 的 iframe sandbox 有 `allow-same-origin`（读得到 parent 的 localStorage）却**没有 `allow-top-navigation`** → `parent.location.replace` 被浏览器拦（实测报 "Unsafe attempt to initiate navigation"）；

## ✅ ⑦ 模型可复现性 —— **已实测 + 已落地（2026-08-03）**

**实测结论（gpt-4o-mini，真实脚本 prompt，4 组参数 × 各 5 次）：`seed` 救不了逐字复现。**

| 参数 | 5 次里有几种不同输出 |
|---|---|
| temperature=0.8，无 seed（原状） | **5 / 5** |
| temperature=0，无 seed | **5 / 5** |
| temperature=0，seed=12345 | **5 / 5** |
| temperature=0.8，seed=12345 | **5 / 5** |

四组 `system_fingerprint` 全部相同（`fp_5d8d1116aa`），即**后端没变仍然不可复现**——OpenAI 的 `seed` 官方就只承诺 best-effort，批式 GPU 推理的浮点非结合性使温度 0 也不确定。

**因此目标从「输出可复现」改为「配置可复现 + 漂移可检测」，已实装：**

1. **模型钉死日期快照**：`gpt-4o-mini` → **`gpt-4o-mini-2024-07-18`**（`.streamlit/secrets.toml` + `.example`）。这是**真正重要的一条**——浮动别名会在采数中途被 OpenAI 重新指向新模型，那才是真混淆。`deploy_check.py` 已有该检查。
2. **每次调用发送 per-trial 派生 seed**：`llm._seed() = (participant_id×100 + round_idx) % 2^31`。用派生而非全局常量，避免所有被试被同一个 seed 推向同一样本（那会人为压缩被试间方差、污染 H6）。
3. **`system_fingerprint` + seed 落进 `llm_done` 事件**（`payload.repro`）——采数中途 OpenAI 换后端时**事后可检测并如实报告**。
4. **temperature 维持 0.8**（创作任务需要；既然确定性拿不到，调 0 只会改变产物性质而无收益）。分析侧的 judge / embedding 另用 temperature=0。

**已验证**：真机调用 seed=702 正确送达、fingerprint `fp_b1b99e3b92` 正确落库、引导 JSON 5 问正常生成；E2E（含 resume/redo）全绿。
**写进 Limitations**：「LLM 输出非逐字可复现（实测 seed 固定仍 5/5 相异）；我们钉死模型快照与参数并记录 system_fingerprint，以保证**过程**可复现与漂移可检测。」——这条实测本身可以进方法附录。

## 🟡 ⑩ 可延后（不影响被试跑通，数据洁净/边角）

- **E 引导数量约束只靠 prompt**：固定 3 维 / 5-7 问 / 追问 1-3 问 / 每问 3-4 选项**没有实时校验**，模型偏离会原样呈现；问答数据已全落库可事后审计。加校验有误杀风险（偏离→误触发 fallback），**暂观察试测实测**。
- **E 追问 prompt 不带历史问题** → 追问轮可能重复问过的问题（概率低，模型能看到当前稿）。
- **LLM 返回空串（无异常）时无错误提示** —— C/D 只剩裸重试按钮、E 终稿/D 修改静默无反应（罕见）。
- **多标签页同 token 并发无守卫** —— 两个标签页各自推进同一被试会互相覆盖（单人单坐的实验，现实概率极低）。
- **final_survey 提交 → 置 done 之间断线**，续接会让被试重填总问卷（秒级窗口）。
- **杂项 nit**：DB 连接用完没显式关；JSON 模式没用官方 `response_format`；逐镜头三标签语义略重叠；「15秒・3カット」硬/软约束没向被试讲清；历史面板默认展开占首屏；进度条在 final_survey 阶段不显示（可接受）；consent + 管理员两个语言器同时渲染显示可能不一致（仅管理员）；`reset_for_next` 后研究员面板仍开着；`load_topics` 对损坏文件静默回退种子主题（不崩但不告警）；C/D 生成中杂散 rerun 会整段重新生成（无幂等守卫）。〔2026-09-24 更正：中国队列**实际触发过** —— C-final 8 次、D-final 5 次调用被重启；E 的非流式引导步骤被重启得更多（E 轮 44% vs C 19% / D 17%），见 14 §4。两批之间不改，写进 Limitations；日本队列靠「别点屏幕」的提示预防〕
