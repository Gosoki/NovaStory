## 2. 数据管理与被试合规

### 2.1 数据都有什么（敏感度分级）

| 数据 | 存哪 | 敏感度 | 备注 |
|---|---|---|---|
| 人口学/筛查（年龄段·专业·AI 使用等） | `participants.demographics_json` / `screening_json` | 低-中 | **以 index 存储、语言无关**，非自由文本；最小化采集 |
| 基线协变量（aiexp/trust/own_trait） | 同上 | 低 | 刻度值 |
| **被试自由文本**（创意 intent / D 的反馈 / 手改稿 / final_survey 留言） | `trials.*` / `participants.final_survey_json` | **中-高** | 可能无意中含可识别信息 → §2.4 |
| AI 生成的每版脚本 | `trials.script_versions` | 低 | |
| 量表作答 / 逐镜头标注 | `questionnaires.*` | 低 | |
| **被试选择的语言** | `participants.lang` | 低 | ja/zh/en，同意页选一次。已进分析管线与监控台（2026-08-03） |
| 行为事件流（时间戳/动作/token） | `events` | 低 | |
| 续接句柄 token | `participants.token` | 中 | 进网址 `?t=`，是会话恢复凭证，非身份 |
| 完成码 | `participants.completion_code` | 低 | 8 位随机大写字母数字(去 0/O/1/I),`secrets` 生成,签发一次不重签 |
| 分镜插图 | `data/storyboard_images/{被试}_{轮次}/{attempt}/` | 低 | 已 gitignore;`backup_db.sh` 会打包 |
| **自愿留下的联系方式**(邮箱 / 是否要视频 / 备注) | `participants.contact_json` | **高**(唯一一列直接个人数据) | 完成页自愿填写。⚠️ 同意书**未写明**（09-02 写入、09-03 删除；日本队列怎么处理见 06 ㉔）;后台表格与 CSV **不导出**此列(`views/researcher.py`) |

| 备份 | `backup/*.db` `backup/storyboard_images-*.tar.gz` | 同主库 | 保存期限与删除承诺同样覆盖这里 |

**不采集**：姓名、学号、IP（Streamlit 默认不落库）、任何直接身份标识。**邮箱只在被试自愿填写完成页表单时**存入 `contact_json`（2026-09-02，见 13 §0.7 / 10）。⚠️ 反代（Caddy/nginx）的访问日志默认会记 IP 与含 `?t=` 续接句柄的 URL —— 部署时要么关掉请求行/查询串的记录，要么把这一条写进「采集」并定保存期。
`participant_id` = 自增整数，与真人身份之间**无映射表**（**匿名**而非假名）。

### 2.2 存储

SQLite 单文件 `data/novastory.db`（WAL 模式），自有服务器原地持久，不用外部 DB。

### 2.3 ⚠️ 第三方数据流出：被试文本会发送到 OpenAI

**这是最容易被忽略的合规点。** 被试写的创意、手改稿、D 的反馈，都会作为 prompt **发送到 OpenAI API**（`core/llm.py`）。即：

- 被试的原创文本会**离开你的服务器、经过第三方（OpenAI）**；
- **同意书必须明确告知**「你输入的内容将由外部 AI 服务（OpenAI）处理以生成脚本」；
- 参考 OpenAI API 数据政策（API 数据默认不用于训练、有限期留存），写进同意书 / 数据管理说明；
- **APPI（日本个人情报保护法）数据越境**：同意书须达越境提供的粒度——**国名 / 保留期 / 是否用于训练**。
  ✅ **已实装（B4, 2026-08-03）**：`consent.body` 三语新增「外部AIサービスの利用」段，写明 **OpenAI 社（米国）**、默认不用于训练、最长 30 天后删除、并要求被试勿填可识别信息。
  **可选加固**：申请 **OpenAI zero-retention 端点**，则「最多保留 30 天」可改为「保持しない」。
- **伦理审查**：✅ **已拍板（B4, 2026-08-03）不提交伦理审查**；上述告知义务照做（与是否送审无关）。

### 2.4 自由文本的可识别信息风险

被试的创意/反馈/留言是自由输入，**可能无意中写入真实人名、校名、具体经历**。处置：
- 同意书说明「请勿填写可识别他人或自己隐私的真实信息」；
- 分析/发表前对自由文本做一遍**人工去标识扫查**（尤其要进论文定性框的摘录）；
- 定性摘录发表前改写/打码。

### 2.5 数据用途与保留

- **仅用于本研究**（学位论文 + 投稿 + 公开数据集若做则匿名后）。
- 不完整数据（未走到 trial_submit / final_survey 的 in_progress 被试）**弃用不进分析**，但匿名记录可留档。
- 保留期：按学位/投稿要求（通常成果发表后数年），到期后处置。

## 3. 采数期监控（研究员后台「🗂 数据管理·监控」）

**每天看的：**

  ⚠️ 绿色进度条会掩盖 `parse_ok=0` 腐蚀，**必须单独看数据健康块**。
- **语言构成**：ja = 日本队列、zh = 中国队列，两者都是正式数据（2026-09-06 方向变更）；只有 **en** 才告警。
- **进行中的会话**（2026-09-05 新增）：编号 / 序号 / 开始时间 / 最后活动 / 已交轮数 / **释放**。
  序号在通过筛查那一刻就被占住且不会自动回收——确认某人不会再回来时点「释放」，序号让给下一位
  （该行标 `dev`、数据保留但不进分析）。⚠️ 对方拿着 `?t=` 回来仍能做完，所以先看「最后活动」。
- **未闭合调用**（2026-09-05 新增）：`llm_start` 减去 `llm_done`/`llm_error`。**失控重试只有 start、

- **配图成功率**（2026-09-05 新增）：429 被 `except pass` 吞掉，被试看到的是空白画框而面板此前一字不提。

- **API 用量**（2026-09-07 新增）：文本调用次数 / 输入·输出 token / 配图张数 / 按 C·D·E 拆分 / 人均。

## 3.5 现场采数（中国中专/职校，2026-09-06 方向变更后新增）

线上滚动招募之外，这一路是**讲座结束后当场用学生自己的手机做**，坑和线上不同：

- **入场时间必须错开。** 一屋子人同时点开链接，会在第 1 轮结束时同步撞上 `gpt-image-1-mini` 的
  分钟限额（30 人齐发约 45 张/分钟）。分两批、间隔 8–10 分钟，零代码成本、收益最大。
  代码侧已加全局并发闸（同时最多 8 张在飞），但档位太低仍不够 —— **先去 OpenAI 后台确认 image 的 IPM**。
- **同一台设备轮流给多人做 → 必须每次清存档。** 续接靠浏览器 localStorage 里的 `?t=` 链接
  （`core/state.remember_resume_url`），不清的话第二个学生会看到「继续上次未完成的作答」并被引进
  前一个人的会话。清法：研究员面板点一次「初始化所有记录」（`forget_resume_url`）。
  学生用自己手机就没这个问题。
- **未成年同意**：`age_idx` 存的是档位序号，事后**分不开 11–17 与 18–20**，同意书里也没有年龄资格条款
  （写了就与题面矛盾）。✅ 已拍板（06 ⑱，2026-09-07）：不设门槛、不细分年龄；后果写进 Limitations。
- **网络**：全程要联网（每轮至少一次 LLM 调用 + 配图）。校园 WiFi 或流量都行，
  但断线会让当前轮从头再来（未提交的创意与脚本会丢），事前说一句能省很多麻烦。
- **讲座材料**：`docs/deck_teens.html`（18 页中文幻灯片）+ `docs/deck_teens_script.md`（讲师稿）。
  ⚠️ 讲师稿 §3 有**禁用清单**：不能拿三个真题目当例子、不能说哪条路更好、不能把「先出再改」说成浪费 ——
  否则直接给因变量施加需求特征。灵魂句「与其做完了返工，不如动手前问清楚」**不能对被试讲**。
- **语言**：中国队列用 `zh`（现为默认）。**日本队列不与中国队列同期开放**（见下条），
  〔2026-09-24 改〕轮到日本队列时**不改 `i18n/translator.py`**（改了要重启，也违反「两批之间不改代码」），
  一律用 **`?lang=ja` 链接**预选日语；闸门的「既定言語」提醒在第二批忽略。见 §3.6。
- 🔴 **两队列必须分批次、不得同期开放**（2026-09-07 拍板，理由见 `docs/paper/10` 同日条目）。
  Williams 序号是全局补空缺、不按 `lang` 分组，同期开放会让两队列各自只摸到一半的条件顺序
  （`[8,4,8,4,8,4]` vs `[4,8,4,8,4,8]`），队列内部的残留效应平衡失效。分批次跑则各自 `[6,6,6,6,6,6]`。
  实操三条：**① 日本队列开始前，中国队列必须完全停止**（不能事后回头补几个中国被试）；
  **② 每队列的完成数尽量落在 18 的整数倍**（36 = 2×18；实收 30/33 会出现 `[6,6,6,6,3,3]` 一类轻度
  不平衡，不致命但要在论文里如实报告实际顺序分布）；**③ 两批之间绝对不改代码、prompt、模型、`topics.json`** ——
  队列与时间、模型版本已经完全共线，任何改动都会让「国别差异」和「版本差异」永久分不开。
  漂移的唯一探针是后台的 `system_fingerprint`→`served_model` 告警（`views/monitor_panel.py:249`），
  **两批采数期间都要盯**。

## 3.6 日本队列开采操作规程（2026-09-24；全部不改代码、不重启）

> 依据：2026-09-24 就绪审计（在 9/23 库副本上用项目自己的分配函数模拟 + 对抗核实）。

**开采前（一次性）**
1. **核对 seq 占用**（服务器，只读）：
   `sqlite3 -readonly data/novastory.db "SELECT seq,COUNT(*) FROM participants WHERE passed=1 AND seq IS NOT NULL AND (json_valid(screening_json)=0 OR COALESCE(json_extract(screening_json,'$.dev'),0)!=1) GROUP BY seq"`
   9/23 副本上是：seq 0–2 各 3，其余各 2 —— 多出来的是 3 条未完成的中国行 **#49/#50/#52**。
2b. ⛔ **不要释放 pid 1**（09-08 讲座现场演示误入库的研究员会话；2026-09-30 用户确认，已在分析代码里剔除 → 中国队列分析 N = 35，见 06 ㉔-1）：补人也**不需要**释放它（见 2c）。释放会让 seq 0 的计数变成 1，日本队列前两人都会被分到 seq 0，18 人就平衡不了。
2. **在监控面板释放 #49/#50/#52**（建议）。不释放也能平衡（日本会从 seq 3 开始），但 #50 已交 2 份问卷，
   拿着 `?t=` 回来补交就会变成**第 37 名中国被试**，违反「中国队列完全停止」。
