### 2.4 我为什么选「降为描述性」而不是「换个有方差的代理」

H4 的 DV 是 `spec_ok = int(n==3 and dur_ok)`，**二值**，而 `02 §8.2` 实测三条件的镜数与时长合规都是 **100%**。
换成 MATTR/HD-D 或「终稿↔首版距离」确实有方差，但它们量的是**词汇多样性/改动量**，不是质量——
把它们改名叫质量 DV 是偷换概念，比诚实地说「没测」更糟，而且会正面撞上 `01` 的禁用措辞表。
所以：`structural_completeness` 继续算继续报，但只作描述性（**三条件都能产出合规分镜**这件事本身就是结论）；
论文与幻灯片必须写「本研究は作品の質（美的・物語的）を測定していない」。

### 2.1 主分析人群在代码里根本不存在 【已核实】

### 2.2 novice 子集功效曲线从没算过，宣传的 dz≈0.48 是全样本数字 【已核实】

- **问题**：`analysis/power_sim.py` 全文没有 novice / subset 字样。B1 和 B2 都明写了「连带动作：功效必须按 novice 子集重算」，至今未做。`11` rank3 已测算：N≈18 时 MDES 约 **dz≈0.70**，不是宣传的 0.48。
- **方法**：`power_sim` 出 N∈{15,18,22,27,36} 的**子集**功效曲线 → 据此把 novice 目标 N 写进 `prereg` → 倒推超招募量。若倒推出的招募量不现实，**现在**就改成 4-of-5 或「novice 为主体 + 经验作调节」。
- **影响**：不算 → 招多少人是拍脑袋；很可能采完 36 人发现 novice 子集只有十几人、功效不足，而那时已经不能再改人群定义（改了就是 HARKing）。
- **工作量**：半天。

### 2.3 两个主终点都没有各自的 SESOI，四象限里的「≈（不劣）」统计上是空的 【已核实】

- **问题**：`prereg.SESOI` 是**一个标量** `0.10`（对应 H4 的结构完整度）。ownership 与 fidelity 两个主终点各自的原始单位界不存在。而 `05` 的四象限解释矩阵里有两个「≈（不劣）」格，靠的就是等价检验。
- **方法**：`SESOI` 标量 → dict：ownership（7 点量表 **0.5 分**）与 fidelity（z 化前的 `imagine_match`）各锁一个原始单位界；写死三分支：**显著→判优 / 不显著→TOST / TOST 不过→inconclusive（不得写「不劣」）**。
- **影响**：不做 → 实际会发生「N 不足 → 不显著 → 写成不劣」，而且这是**事先计划**的，比事后 HARKing 更难辩解（`11` 致命级 #5）。
- **工作量**：半天（定界要论证，实装很快）。

### 2.4 H4 的质量 DV 结构性触顶 【已核实定义】

- **问题**：H4 主质量 DV = `spec_ok`，定义是 `int(n == 3 and dur_ok)`（`v3.py:111`）——**一个二值变量**。而 `02 §8.2` 的选型实测里，3 镜合规 100%、15 秒合规 100%。配对差 SD≈0 时 TOST 要么无结论、要么无信息。
- **方法**：二选一并写进冻结产物：**①** 换有真实方差的客观质量代理（MATTR/HD-D、同题内两两相似度、终稿↔首版距离），或把盲评保真升为共同 DV（另设单位正确的 SESOI）；**②** H4 降为描述性，明说「本研究は作品の質を測定していない」。无论哪条都要写「零方差→无结论」的后手。
- **影响**：不处理 → H4（质量非劣）这条腿在数据上是空的，而它正是「E 提高保真但不牺牲质量」这个核心主张的一半。
- **工作量**：拍板 + 半天到一天。

### 2.5 保真主终点构念自循环

- **问题**：`mine_ratio`（逐镜头「主要是我的想法」占比）测的是**人类贡献量**，与 own3（所有权）同构念；`q.imagine`（终稿与想象的接近度）**没有时点锚定**，而 E 条件的参照系被 E 自己塑造过（AI 先问了问题，被试的「想象」已被重塑）。
- **方法**：`mine_ratio` → `1 − ai_against_ratio`（或移出主复合）；**条件流水线之前加一屏事前意图快照**（3 条「必ず入れたいもの」，三条件同文）；`q.imagine` / `q.violation` 三语加时点锚定；`questionnaire.py` 里 E 专属的 `ai_q_best` 移到逐镜头标注**之后**（现在是先复读答案再打标注）。
- **影响**：不改 → 「E 保真最高」在 `mine_ratio` 这条腿上是**定义性的**（E 让人投入更多 → 贡献量更高 → 保真更高），审稿人一句「E 到底提高了保真，还是重新定义了意图？」现有设计答不了。
- **工作量**：不到一天（`11` 的估计）。

### 2.6 冻结既没有产物，也盖不住能翻转结论的旋钮 【已核实】

- **问题**：`prereg.as_dict()` 存在，但**没有 CLI、没有 sha256、没有 dump 入口**——冻结产物要手工产生，而仓库里没有任何工具做这件事。更关键的是：`SPEC_TOL_SEC`（直接决定 H4 主 DV `spec_ok`）在 `v3.py` 里，**不在 `as_dict()` 的冻结范围内**；`_SHOT_FIELDS` 同理。
- **原因**：B3 拍板「不做第三方预注册，改内部冻结」时只定了原则，没定产物规格。
- **方法**：写 `scripts/freeze_prereg.py`：prereg 常量 + `SPEC_TOL_SEC` / 各 `_LEGS` / z 作用域 + `analysis/*.py` 与 `core/shots.py` 逐文件 sha256 + git HEAD + `pip freeze` lock → canonical JSON。冻结当天顺序：清干净工作树 → 删 `analysis/metrics.py`（v2 遗留）→ `make smoke` → **单独一个 commit 只放冻结产物**（message `FREEZE: analysis plan, before any main-collection data`）→ **push 到 origin**。`make smoke` 加断言：冻结值 == 实际 import 值。
- **影响**：B3 的全部防御力就在这个产物上。没有它，「我们没有 HARKing」的证据只有「相信我们的 git 历史」——而本地 git 历史是可改写的，这正是 `11 §5.4` 已写进 Limitations 的那条。
- **工作量**：一天。

### 2.7 冻结时点未定，两份权威文档给出相反答案

- **问题**：`05 §4` 写「试测后锁定头三项」；`11` P0-C 指出**试测数据就是真人数据**，用它来定分析计划就是事后决策。两份文档口径相反，`05` 也没标注被质疑。

- **影响**：不定 → 试测数据静默混进正式样本，且用真人数据决定分析计划，这是比事后 HARKing 更难辩解的形态。

### 3.3 试测本身怎么组织，一个字都没写

- **方法**：见 2.7 的 (A)/(B)。另定 n、招募来源（明确不得是知情者）、观察方式。
- **影响**：与 2.7 相同——试测数据静默混入。
- **工作量**：拍板 1 小时。

### 3.4 实验实施形态（对面监督 vs 完全远程）从未拍板，两份文档各自假设了不同答案

- **问题**：`12` 的整个韧性验证按「远程、多人并发、无人看管」写（24 人同时通过筛查、多标签页、伪造 token）；但 `12 §4②` 又把 E 首轮生成持续失败判定为「实验员该介入的现场事故」，`12 §3` 还有「每场前点一次模型探测」「场后 reset」——这两条只有**对面单人依次做**才成立。
- **原因**：代码同时支持两种形态（有 reset 按钮也有 token 续接），文档在不同时期按不同假设写。
- **方法**：二选一：**(A) 对面/半监督**（与 `12 §3`/`§4②` 一致，但招募速度受实验员时间限制）；**(B) 完全远程**（招募快，但 `12 §4②` 的兜底不成立，需另加「E 首轮连续失败」的自救出口）。
- **影响**：这一条决定 3.2（渠道）、3.5（SOP）、3.6（中断处置）三条的具体内容。先做那三条而不定这条，会做出互相矛盾的产物。
- **工作量**：拍板 30 分钟。

### 3.5 研究员现场 SOP 不存在

- **问题**：`12 §3` 只覆盖机器侧（跑三条链、模型探测、别改题库、盯三个数、备份）。面向真人的那一半没有：被试坐下前说什么、被试问「哪一轮的 AI 更好」怎么答（**必须统一回避，否则临场解释成为未记录的处理变量**）、什么时候点 reset、每场后要做哪几件事。
- **方法**：写一页可打印的 checklist：每场前 3 步 → 开场标准话术（ja 逐字稿，只讲流程不讲假设）→ 常见提问的标准答法表 → 每场后 3 步（记录场次日志 → 跑备份 → reset）→ 当日收尾（核对 seq 平衡、导出监控三个数）。
- **影响**：没有统一话术，实验员的临场解释直接威胁被试内比较；「每场后备份」`07` 已明写为要求，没有 checklist 必然漏做。
- **工作量**：半天（需先定 3.4）。

### 3.6 离脱处置与 seq 补发机制不存在

- **问题**：`12 §1②` 已确认「被试行入库后走不完 = 那个 seq 被永久消耗」，`11` rank3 指出 `seq = n % 18` **无法定向补空格**。但没有任何文档写：多久没动作算离脱、要不要人工补这个 seq、离场者能否重来、OpenAI 大面积故障时该场如何标记。
- **方法**：①定义离脱判定（建议 24 小时无事件 → `status='abandoned'`）；②给后台加「指定下一位被试的 seq」入口（十几行），**或**事先声明「不定向补，靠超招募随机填」并接受各 seq 完成数不均；③写明故障时的场次标记与是否重招同一人（重招则条件暴露顺序作废）。
- **影响**：18 个 seq 每格要 2 名完成者，一个被消耗的 seq 在随机轮转下平均要多招 **18 人**才能补上。不定向补，实际招募量会远超 `11` rank3 已经算出的三位数。
- **工作量**：拍板 1 小时；选定向补另加半天。
