# 19 · 系统审计：按中国数据找逻辑问题并修（2026-10-29）

> **为什么做**：用户要求「审计整个项目有没有可以优化或者逻辑上的问题，事无巨细……根据现在远端数据库上的数据……优化系统逻辑，无人值守……当然不能修改得完全不一样了」。
> **数据**：这台 Mac 连不到服务器（没有它的 SSH 入口），用的是 2026-09-23 拉下来的完整副本（`data/novastory.db`，中国队列全部数据）。日本队列还没开采，服务器上此后没有新的正式数据。
> **怎么做**：五路只读审计并行（被试流程与界面 / 数据层与运维 / 分析管线在日本 4 条件数据上 / 用中国数据找过程问题 / 提示词与 LLM 交互），主会话逐条核实后修改。每处修改都标了「会不会改变 C / D / E 被试看到的东西」—— 中日可比是硬约束。
> **本文只含汇总数字，不含被试原话**（可以进 git）。

## 0. 结论

- **最大的问题找到了，而且修好了**：中国 E 轮 46% 的「请求重启」与「约一半请求没记 usage」是同一个原因 —— 页面一 rerun（等待中点了屏幕上残留的旧按钮、双击、手机重连、返回键），正在跑的 AI 调用就被作废、从头重发。API 本身完全正常（365 次调用 0 错误 0 重试）。日本 F 每轮要等 2–4 次，不修会更严重。
- **研究员工具在日本采集中会误导**：监控面板的健康读数混着中国数据（「未完成调用」一开采就是 54%，07 §3.6 第 8 步「超过 25% 就暂停」第一天就误触发）、直接显示日本的因变量均值、释放按钮不保护只差总问卷的有效被试；研究员面板的「分析结果」混算中日且不过门控。都已修。
- **有一处会把中国的确证数字改掉**：`make v3 events embed EMBED_LANG=ja` 会清空中国的 embedding，保真 D−C 变「显著」。已改为在发 API 之前拒绝执行。
- **日本的 E 提示与中国不同构**（3 处，示例会渗进选项）：已把日语、英文对齐到中国用的中文版本。
- 中国结果全程不变：`make stats-zh` 逐字相同；481 份稿子（终稿 + 版本历史 + 机器基线）的解析结果指纹改前改后相同。

## 3. 没改，及原因

| 问题 | 为什么不改 / 怎么处理 |
|---|---|
| E 选项顺序没随机（首项被选 41% vs 期望 29%）、D 输入框示例锚定修改请求、E / F 专属题紧挨逐镜头标注、注意力题位置 | 改了会让中日 C / D / E 不可比（B 类）。日本照报选项位置分布、D 请求主题，写进局限 |
| 日语 E 提示的示例物件是「財布」，日本第 1 题是「切符」 | 示例与中文同构（中国用的也是钱包），不动；日本采完统计第 1 题 E 里「財布」出现而创意里没有的次数，写进局限 |
| 轮中重载从本轮开头重做（中国 5 轮，4.8%） | 设计如此；改成持久化轮内进度风险中等、且中日处理方式会不同。保留 `n_resumes` 作协变量 |

## 4. 对中日可比性的影响（写进 08 §9 与偏离记录）

- 中日两国的**技术摩擦**从此不同：日本的等待不再因误触而重来（中国 E 46% 的 trial 碰到过）。提示词、题目、流程、问卷都没变；E 的日语提示改为与中文同构（提高可比性）。
- 日本的「请求重启」敏感性改用 `n_llm_reattach`；中国用 `n_llm_unclosed`（旧代码口径）。两者都是「被打断过」的读数，但旧代码下被打断 = 重发，新代码下被打断 = 接上，严重程度不同。
- 研究员工具与分析脚本的修改不影响任何因变量。
