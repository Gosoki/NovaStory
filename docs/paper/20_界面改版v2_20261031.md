## 1. 为什么改（v1 的实测问题）

用同一个自动走查脚本把 v1 的 29 屏桌面（1280×860）+ 手机（390×844）都拍了一遍，问题按影响排：

1. **手机首屏全是页面框架。** 每页顶部 6rem 留白 + 44px 的两行 h1（「NovaStory · ショート動画の絵コンテ制作」）+ 副标题；轮次页再叠一根进度条、一条分割线、一个与进度条写同一句话的 h2、一串折成两行的箭头步骤条、一个「今回のお題」h3。**手机 844px 的首屏里看不到任何要做的事**，创意输入框要往下滑 1–2 屏；桌面 860px 的首屏里输入框也在折线以下。
2. **第 1 轮开局进度条显示 0%**；同意 / 背景问卷 / 说明 / 总问卷全程没有进度（06 ⑮）。
3. **日本被试会看到英文**：Streamlit 1.60 的下拉框占位是「Choose an option」，背景问卷一页 4 处。
4. **`<html lang="en">`**：日文汉字的字体回退不确定（Windows 上可能落到中文字体，字形不对），浏览器的日文断行规则也不生效（手机上标题断成「絵コ / ンテ制作」）。
5. **量表锚点读起来像属于下一题**：背景问卷里锚点行紧贴着下一题题干，中间没有间距。
6. **禁用的按钮看起来能点**：v1 用 `!important` 把 primary 按钮涂成实心绿，同意页「未勾选时禁用的开始按钮」也是实心绿。
7. 提示框整段彩色字（蓝 / 绿 / 黄）、表单里分节标题是 2.25rem 的大字、选中的量表格只是浅蓝底（答到十几题时很难扫出漏答）、对话头像是 Streamlit 默认的橙色机器人与红色笑脸、历史面板固定 480px 高（只有一版时下面一大块空白）、生成中的状态框展开却是空的、流式输出按 markdown 渲染（「1.」变列表、两行并成一段，生成完瞬间换排版）。

## 3. 改了什么

**设计语言：和纸 / 墨 / 青。** 暖白纸色底（与絵コンテ用纸的奶白同一个温度）、白卡片承载内容、墨色正文与「决定」按钮、不带紫的海蓝（浅 `#1565c0` / 深 `#64b5f6`，色相约 210°）作强调色与 AI 动作。单一真源仍是 `app.py` 的 `--ns-*` 令牌；`.streamlit/config.toml` 把同一组颜色交给 Streamlit 自己的组件。浅色 / 深色两套，跟随被试操作系统。对比度（WCAG）：正文 14.5、弱化字 4.8（浅）/ 6.9（深）、强调色 5.3（浅）/ 8.3（深）、按钮字 ≥ 5.0，全部过 AA。

〔同日按用户反馈调整〕① 初版强调色是偏靛紫的瑠璃色（浅 `#1e50a2` / 深 `#8fabf5`），用户：「紫色有点阴间」→ 换成上面的海蓝；② 初版把提示框做成「左竖线 + 淡底 + 正文色字」，像引用块，用户：「还是之前那种整个都是色块的好用」→ 回到 v1 的整块色块 + 同色系深色字，只是颜色换成新配色（字 / 底对比度 6.8–8.5）；③ 用户：「下一步需要操作的地方需要点提示，比如先提示一下题目，然后引导到输入框」→ 加了下面表里「下一步提示」一行。

| 页面 / 组件 | v1 | v2 |
|---|---|---|
| 页头 | 每页 44px h1 + 副标题 + 6rem 留白 | 同意页一块标题区；其余页一条细品牌栏（标记 + NovaStory │ 副题），底边是**全流程进度线**（06 ⑮ (b) 的轻量版，不加任何字） |
| 轮次头 | 进度条 + 分割线 + h2 + 箭头步骤条 + 「今回のお題」h3 | 一块：「第 i / n ラウンド」+ 每轮一格 + 圆点步骤条（当前步高亮；手机上只显示当前一步的名字） |
| 题目 | 小标题 + 描边框 | 白卡：眉标「今回のお題」→ 题名 → 情境 → 选择示例（照旧弱化）→ 规格胶囊（文字一字不差） |
| 7 点量表 | 题干 + 按钮行 + 锚点，题与题之间只有一条分割线（背景问卷连线都没有） | 一题一块、块间细线；选中格实心蓝底白字 |
| 下一步引导（动效） | 无 | **新手引导**（`views/_tour.py`，用户：「不是加文字引导，是要动效，像新手引导一样」）：第 1 轮页面变暗，聚光圈带呼吸光环依次框住 题目卡 → 本轮说明框（各条件的操纵说明，不能跳过）→ 输入区，气泡「1/3 次へ … 3/3 書きはじめる」，最后把光标放进输入框。**只在第 1 轮、每位被试一次**（用户：「只有第一次有这个引导就行了」；此前第 2 轮起还会让三处各闪一下，已去掉；第 2 轮起改为只提醒题目，见本格末尾）：记号存 localStorage、键里带被试编号——刷新、关掉标签页再用续接链接回来都不重演，同一台设备上的下一位被试照常会看到；被试已经在写就不演，离开创意页立即撤场；纯前端、不记事件、尊重「减少动态效果」。另：输入框常亮光晕（F 的回答框同样）；问卷里第一道没答的必答题套一圈细框、答一题挪一题。D 的「请 AI 改」框**刻意不高亮**（那是被试在「再改 / 提交」之间的自由选择）。〔2026-11-02〕第 2 轮起写创意页的**题目卡呼吸两下、之后常亮一圈**（用户：「第二轮开始，题目要提醒一下……闪一下，然后有一圈提醒就行了」；与 F 回答框同一个效果）：新题换上时版面与上一轮一模一样，容易没注意到换了题；只在写创意这一步，四个条件相同，同一步里重跑不重播，尊重「减少动态效果」 |
| 提示框 | Streamlit 默认整块色块 | 仍是整块色块，颜色换成新配色（见上） |
| 背景问卷 | 默认表单、英文占位 | 白卡表单、分节小标题、本地化占位（選択してください / 请选择）；竖排单选变成整行可点的选项卡（手机点按区域从 ~24px 变成 ~44px），是 / 否变成胶囊 |
| D/E/F 生成后 | 固定高历史面板、默认头像、两颗按钮贴在一起 | 历史面板随内容伸缩（最高 480px）、只留展开框一层框、人形 / 星芒头像（手机上不显示头像）；历史里的各版稿子用看稿排版（§3.2）；D 的「请 AI 改」与「提交」照 v1 平铺（不套卡片：两条路哪一条有额外的框都是在推它） |
| E 的引导题 | 小标题 + 灰字进度 + 加粗题面 | 一题一张卡：「質問 2 / 4」+ 每题一个点 → 题面 → 为什么问 → 选项（胶囊）→ 自己写 → 前后翻页 |
| F 的采访 | 默认头像、内联灰字复述 | 与历史面板同一套头像；复述弱化、题面加粗，都逐字转义 |
| 问卷逐镜头标注 | 描边框 + 分割线 | 一镜一张卡，镜号圆圈与絵コンテ纸上的同形；三个选项是分开的胶囊 |
| 等待 AI | 空的展开状态框 + markdown 流式输出 | 一行状态 + 与最终稿同排版的逐字输出（看稿排版，§3.2） |

### 3.1 说明精简（2026-10-31，用户：「整个项目你优化一下，可以适当减少说明」）

做法：只读审计把界面上每一条说明分成「协议 / 测量 / 伦理（不动）」「重复 / 装饰（可删）」「研究员用的长说明（折叠或改成 ⓘ 提示）」，再由独立验证员逐条反驳；被驳回的保持原样（例：说明页两条强调句、F 的致谢、修改提示等——它们会影响创意长度、手改量或所有权框定）。

- **参与者侧**：同意页去掉「表示言語」标签（三颗语言胶囊自带语言名）；背景问卷提示删掉「すべて選択式で」（同屏可见，其余逐字）；说明页例子下的灰字只留「実際のお題は、このあとすぐ出てきます」（前两句与同页蓝框、样例导语重复）；创意页说明框去掉「📍 今回の流れ：」标签（与步骤条重复）；生成中的回显框标签改为「あなたのアイデア」；问卷镜头卡只留镜号圆圈（「ショット 1」文字移给读屏）；完成页「あなたの完了コード」、完成码用途与「可以关页面」缩成一句（后者只删与标题重复的前半句）、联系表单按钮「メールアドレスを送信」。
- **研究员后台**：监控面板标题与各小标题缩短；恒为 0 的「筛除」卡去掉（2026-09-07 起无人被筛）；novice 人数、口径范围、用量说明、Williams 平衡判据移进对应标题 / 卡片的 ⓘ；语言构成在正常时只显示一行，混入 en 时的告警保持完整原文；会话列表只留「序号不会自动回收」这一条；「📊 数据分析」整体收进默认收起的展开框，三个人群开关的长说明移进 ⓘ（「采集期间不要勾 ja」仍写在标签上）；回答倾向面板只留「采集期间别看 ja」的告警；侧栏与测试工具的说明移进 ⓘ。数据健康告警一条未动。
- 若日本队列采用 v2，参与者侧的这几处文字变化要与界面一起写进 08 §9 的偏离清单（中国队列看到的是原文）。

### 3.2 历史面板与看稿排版（2026-11-02，用户截图：历史里「3.」单独一行、上下大片空白，「看看有没有更好的展示方式」）

- **根因（v1 起就有）**：逐字显示用的 `<div style="white-space:pre-wrap">` 把换行原样写进 markdown 源码，而 CommonMark 的 HTML 块遇到空行就结束、后面的文字又按 markdown 排。AI 稿按提示词镜与镜之间正好空一行，于是第 2 镜起「2.」「3.」变成有序列表的序号、上下各空出一大块，`*` 会变斜体。所有逐字显示处都中：**C 的只读稿**、历史面板、生成中的流式输出、F 的回答回显。**中国队列看到的就是这样**——只影响显示，库里存的稿子、事件、编辑框里的文字都不受影响。修法：换行写成 `&#10;`，整段 HTML 留在源码的同一行（`views/_streaming._one_line`）。预览的桩稿原来没有空行，所以一直没暴露；现已按真实排版补上空行。
- **看稿排版**（`views/_streaming.script_view`；C 的只读稿 / 历史各版 / 生成中三处同一排版，生成完不跳）：单独成行的镜号画成圆圈（与问卷镜头卡同形），【画面】【秒数】【カメラ】【セリフ・音】画成小标签，镜与镜之间留白。**只加样式、不改字**：逐行原样转义，认不出镜号的稿子（被试手改过的）就是逐行原文；【】和「1.」的点用 0 号字留在页面里——从历史里复制旧版贴回编辑框，标签与编号都还在（实测复制结果与编辑框逐行相同），分镜解析不受影响。编辑框本身仍是原文。
- 历史面板：去掉内层滚动框的边框（只留展开框一层）；手机上不显示头像（390px 上头像那一列吃掉 ~45px，稿子一行只剩八九个字；谁说的看小标题与底色）；E 的「ガイド回答」一问一答成组（题面紧贴回答，组与组之间留白）。
- 镜号圆圈的数字从 Georgia 换成正文字体（Georgia 是旧式数字，3、4、5 下沉，在圆圈里不居中），问卷镜头卡同步。
- 顺带修了一个整页问题：换页后第一次重跑（被试第一次输完离开输入框、点任何控件），`_scroll` 那一格「滚回顶部」的脚本消失，后面整页元素错一位、全部重新挂载——第 2 轮的题目卡会再闪一遍，F 回答框的呼吸也会重播。现在没有滚动请求时放一个空的 `st.html` 占住这一格（`views/_scroll.apply_pending`）。

**涉及文件**：`app.py`、`.streamlit/config.toml`、`views/{round_common,_tour(新),_scale,questionnaire,screening,consent,intro,_postgen,guidance,interview,_streaming,_scroll,_storyboard,group_f,monitor_panel,analysis_panel,tendency_panel,sidebar,devtools}.py`、`core/state.py`（只改续接提示条的样式字符串）、`i18n/locales/*.json`、`scripts/{ui_preview(新),dev_smoke_e2e}.py`、`Makefile`（`make preview`）。
