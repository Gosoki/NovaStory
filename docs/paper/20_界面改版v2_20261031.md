## 1. 为什么改（v1 的实测问题）

用同一个自动走查脚本把 v1 的 29 屏桌面（1280×860）+ 手机（390×844）都拍了一遍，问题按影响排：

1. **手机首屏全是页面框架。** 每页顶部 6rem 留白 + 44px 的两行 h1（「NovaStory · ショート動画の絵コンテ制作」）+ 副标题；轮次页再叠一根进度条、一条分割线、一个与进度条写同一句话的 h2、一串折成两行的箭头步骤条、一个「今回のお題」h3。**手机 844px 的首屏里看不到任何要做的事**，创意输入框要往下滑 1–2 屏；桌面 860px 的首屏里输入框也在折线以下。
2. **第 1 轮开局进度条显示 0%**；同意 / 背景问卷 / 说明 / 总问卷全程没有进度（06 ⑮）。
3. **日本被试会看到英文**：Streamlit 1.60 的下拉框占位是「Choose an option」，背景问卷一页 4 处。
4. **`<html lang="en">`**：日文汉字的字体回退不确定（Windows 上可能落到中文字体，字形不对），浏览器的日文断行规则也不生效（手机上标题断成「絵コ / ンテ制作」）。
5. **量表锚点读起来像属于下一题**：背景问卷里锚点行紧贴着下一题题干，中间没有间距。
6. **禁用的按钮看起来能点**：v1 用 `!important` 把 primary 按钮涂成实心绿，同意页「未勾选时禁用的开始按钮」也是实心绿。
7. 提示框整段彩色字（蓝 / 绿 / 黄）、表单里分节标题是 2.25rem 的大字、选中的量表格只是浅蓝底（答到十几题时很难扫出漏答）、对话头像是 Streamlit 默认的橙色机器人与红色笑脸、历史面板固定 480px 高（只有一版时下面一大块空白）、生成中的状态框展开却是空的、流式输出按 markdown 渲染（「1.」变列表、两行并成一段，生成完瞬间换排版）。

## 2. 不变的（测量不变量）——以及怎么证明的

改版**只动呈现**。以下逐条保持与 v1 相同：

| 不变量 | 证据 |
|---|---|
| 所有题目、选项、锚点、说明文字 | 三语文案只新增 1 个键（`common.select_placeholder`），其余逐字未动；`make i18n` 421 键一致 |
| 同意书指纹 / 完成页联系说明指纹 | ja `5bdfa1a0b8849a98` / `3837836b87de7ead`，zh、en 同样逐位相同（v1、v2 各算一遍） |
| 流程、条件、轮数、题序、提示词、生成逻辑 | `core/prompts.py`、`core/llm.py`、`core/db.py`、`analysis/` 一行未改 |
| **写进库里的每一条数据** | v1 与 v2 各跑一遍 `dev_smoke_e2e`（zh 3 条件 / ja 4 条件），逐条比对：事件序列（类型 + 轮次 + payload 字段）、问卷答案、试次（含每一版稿子、手改字数）、被试行 —— **zh 65 / ja 91 条事件全部相同** |
| 控件的 key、按钮文字、单选 / 下拉的出现顺序 | E2E 按 key、按钮文字、按位置驱动，中日两遍全过 |
| 会影响「写多少」的输入框高度 | 创意 90px、修改请求 80px、采访回答 90px、编辑框 320px，都没动 |
| **「再让 AI 改」与「就这版提交」同样醒目** | 两颗都是同尺寸的实心按钮（瑠璃 / 墨），对应 v1 的蓝 / 绿。D/E 的 `n_ai_rounds` 是因变量，哪颗更显眼本身就会推行为，所以刻意不做主次 |
| E 追问时「取消、回到稿子」的醒目程度 | 维持 v1 的普通按钮（`guidance_cancel` 是被计数的 E 行为，不能把它降成一行小字） |
| 关闭「运行中变暗」、AI 等待时藏旧按钮、iOS 输入框 16px、关橡皮筋刷新、桥接 iframe、分镜表钉角落 | 原样保留（规则搬进新 CSS，注释一并保留）；浏览器实测：续接网址照常写进 localStorage，等待中残留的旧元素全部隐藏且点不到 |

## 3. 改了什么

**设计语言：和纸 / 墨 / 瑠璃。** 暖白纸色底（与絵コンテ用纸的奶白同一个温度）、白卡片承载内容、墨色正文与「决定」按钮、瑠璃蓝作强调色与 AI 动作。单一真源仍是 `app.py` 的 `--ns-*` 令牌；`.streamlit/config.toml` 把同一组颜色交给 Streamlit 自己的组件。浅色 / 深色两套，跟随被试操作系统。对比度（WCAG）：正文 14.5、弱化字 4.8（浅）/ 6.9（深）、强调色 7.1、按钮字 ≥ 5.4，全部过 AA。

| 页面 / 组件 | v1 | v2 |
|---|---|---|
| 页头 | 每页 44px h1 + 副标题 + 6rem 留白 | 同意页一块标题区；其余页一条细品牌栏（标记 + NovaStory │ 副题），底边是**全流程进度线**（06 ⑮ (b) 的轻量版，不加任何字） |
| 轮次头 | 进度条 + 分割线 + h2 + 箭头步骤条 + 「今回のお題」h3 | 一块：「第 i / n ラウンド」+ 每轮一格 + 圆点步骤条（当前步高亮；手机上只显示当前一步的名字） |
| 题目 | 小标题 + 描边框 | 白卡：眉标「今回のお題」→ 题名 → 情境 → 选择示例（照旧弱化）→ 规格胶囊（文字一字不差） |
| 7 点量表 | 题干 + 按钮行 + 锚点，题与题之间只有一条分割线（背景问卷连线都没有） | 一题一块、块间细线；选中格实心瑠璃底白字 |
| 背景问卷 | 默认表单、英文占位 | 白卡表单、分节小标题、本地化占位（選択してください / 请选择）；竖排单选变成整行可点的选项卡（手机点按区域从 ~24px 变成 ~44px），是 / 否变成胶囊 |
| D/E/F 生成后 | 固定高历史面板、默认头像、两颗按钮贴在一起 | 历史面板随内容伸缩（最高 480px）、人形 / 星芒头像；D 的「请 AI 改」输入 + 说明 + 按钮收进一张卡，与下面的「提交」分开 |
| E 的引导题 | 小标题 + 灰字进度 + 加粗题面 | 一题一张卡：「質問 2 / 4」+ 每题一个点 → 题面 → 为什么问 → 选项（胶囊）→ 自己写 → 前后翻页 |
| F 的采访 | 默认头像、内联灰字复述 | 与历史面板同一套头像；复述弱化、题面加粗，都逐字转义 |
| 问卷逐镜头标注 | 描边框 + 分割线 | 一镜一张卡，镜号圆圈与絵コンテ纸上的同形；三个选项是分开的胶囊 |
| 等待 AI | 空的展开状态框 + markdown 流式输出 | 一行状态 + 与最终稿同排版的逐字输出 |
| 完成页 | 绿框 + 绿框 + 黄框，完成码是一行小代码 | 居中的完成标记 + 标题，完成码放大、虚线框；其余文字与顺序不变 |
| 续接提示条 | 橙色内联样式 | 令牌配色，「前回の続きから再開する」做成可点的胶囊按钮，避开 iPhone 底部手势条 |
| 其他 | — | `<html lang>` 设成会话语言（字体回退与日文按词组断行生效）；标题旁的锚点图标去掉；禁用按钮看得出是禁用；研究员后台宽版 1320px |

**涉及文件**：`app.py`、`.streamlit/config.toml`、`views/{round_common,_scale,questionnaire,screening,consent,intro,_postgen,guidance,interview,_streaming,_scroll}.py`、`core/state.py`（只改续接提示条的样式字符串）、`i18n/locales/*.json`（+1 键）、`scripts/ui_preview.py`（新）、`Makefile`（`make preview`）。

## 4. 验证

- `make i18n`（421 键 × 3）· `make smoke-e2e`（zh、ja；ja 每屏扫简体中文混入）· `make robust`（A–G 全绿）—— 全过。
- v1 / v2 数据层逐条比对（§2）—— 全部相同。
- 浏览器实测（Playwright + 本机 Chrome）：v1、v2 各走完整流程（桌面 / 手机，v2 另加深色）；续接网址写入 localStorage；AI 等待中旧元素隐藏；续接提示条渲染；研究员后台解锁与渲染。

## 5. 没做的 / 局限

- **真机没测**：iOS Safari、Android Chrome 上的实际观感要在 07 §3.6 第 4d 步的试跑里一起看（原本就要在手机上看等待画面）。`word-break:auto-phrase` 只有 Chromium 119+ 生效，其他浏览器退回普通断行，不影响功能。
- 新 CSS 依赖 Streamlit 1.60 的 `data-testid`（与 v1 同样的依赖方式）；升级 Streamlit 后要重拍一遍截图看。
- 若日本队列采用 v2，中日两个队列的**界面呈现**不同（题目、流程、数据层相同）——这是 06 ㉗ 要拍板的事，采用的话要写进 08 §9 的偏离清单。
